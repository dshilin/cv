# Общее техническое задание

## 1. Назначение

Разработать процесс подготовки актуального резюме и сопроводительного письма под конкретную вакансию через подключённый LLM API. Общая backend-интеграция провайдеров описана отдельно в [SPEC-006](../superpowers/specs/2026-09-28-llm-provider-integration-design.md); эта спецификация описывает прикладной сценарий, включая ввод вакансии и документы, а не реализацию gateway.

## 2. Цель

Получать на выходе:

- актуальное резюме кандидата;
- версию резюме, адаптированную под конкретную вакансию;
- сопроводительное письмо;
- при необходимости — краткую версию профиля для отклика на job-сайтах;
- рекомендации по усилению позиции кандидата и устранению пробелов.

## 3. Входные данные

Пользователь предоставляет:

1. Текущее резюме или информацию о профессиональном опыте.
2. Описание вакансии или ссылку на вакансию.
3. Желаемую должность.
4. Предпочтительный город, формат работы и уровень занятости.
5. Информацию об образовании, сертификатах и языках.
6. Ключевые профессиональные достижения.
7. Желаемый уровень дохода — при необходимости.
8. Дополнительные требования к стилю резюме и сопроводительного письма.
9. Предпочтительный язык документов.
10. При наличии — ссылки на портфолио, GitHub, LinkedIn или сайт.

Запрещается выдумывать опыт, должности, компании, навыки, достижения, цифры и сертификаты, отсутствующие во входных данных.

## 4. Основной сценарий работы

1. Пользователь подключает свои API credentials для провайдера и проверяет подключение.
2. Создаёт отдельную версию отклика: вводит описание вакансии или выбирает вакансию в приложении, затем указывает специализационный профиль.
3. Выбирает подключённые провайдера/модель и режим длины письма.
4. Backend отправляет выбранной модели требования вакансии и минимально необходимые подтверждённые факты профиля.
5. Модель возвращает анализ, соответствия, пробелы, вопросы, адаптированное резюме и письмо.
6. Система проверяет формулировки по подтверждённой базе фактов; неизвестное остаётся вопросом или пометкой на проверку.
7. Пользователь проверяет и редактирует документы. Повторная генерация/правка сохраняет отдельную редакцию.
8. Пользователь копирует готовые документы и отправляет их работодателю вне приложения.

## 5. Требования к резюме

Резюме должно:

- соответствовать конкретной вакансии;
- содержать релевантный профессиональный опыт;
- использовать терминологию из описания вакансии без искусственного переизбытка ключевых слов;
- подчёркивать измеримые результаты;
- быть структурированным и легко читаемым;
- не содержать неподтверждённых фактов;
- учитывать уровень должности;
- быть пригодным для ATS-систем;
- иметь единый стиль оформления;
- не содержать орфографических, фактических и логических ошибок.

Рекомендуемая структура:

1. ФИО и контакты.
2. Желаемая должность.
3. Краткое профессиональное резюме.
4. Ключевые компетенции.
5. Опыт работы.
6. Образование.
7. Сертификаты и дополнительные квалификации.
8. Языки.
9. Портфолио и ссылки.

## 6. Требования к сопроводительному письму

Письмо должно:

- быть адресовано конкретной компании и должности;
- демонстрировать соответствие кандидата вакансии;
- содержать 2–4 наиболее релевантных аргумента;
- опираться только на подтверждённый опыт;
- соответствовать выбранному пользователем режиму длины: 150–300 слов или 800–1500 символов;
- позволять выбрать режим длины переключателем на фронтенде;
- иметь профессиональный, естественный и не шаблонный стиль;
- не дублировать резюме полностью;
- завершаться корректным призывом к контакту;
- иметь версии на русском и английском языке при необходимости.

## 7. Формат результата

Результат генерации должен содержать в следующем порядке:

### Анализ вакансии

- должность;
- ключевые требования;
- обязательные навыки;
- желательные навыки;
- ключевые слова для ATS;
- соответствие кандидата;
- выявленные пробелы.

### Адаптированное резюме

Готовый текст резюме, который можно перенести в Word, PDF или профиль на job-сайте.

### Сопроводительное письмо

Готовое письмо для отправки работодателю.

### Рекомендации

- что уточнить;
- какие достижения добавить;
- какие навыки подтвердить;
- какие формулировки усилить;
- какие элементы убрать.

## 8. Режимы работы

Необходимо предусмотреть следующие режимы:

1. Создание резюме с нуля.
2. Обновление существующего резюме.
3. Адаптация резюме под вакансию.
4. Подготовка сопроводительного письма.
5. Подготовка резюме и письма одновременно.
6. Перевод документов на другой язык.
7. Сокращение резюме до одной страницы.
8. Подготовка версии для ATS.
9. Подготовка нескольких вариантов под разные должности.
10. Проверка готового резюме и письма.

## 9. Требования к стилю

Генератор должен:

- писать конкретно и профессионально;
- избегать канцелярита и чрезмерно общих фраз;
- использовать активные глаголы;
- заменять обязанности результатами, если данные позволяют;
- сохранять достоверность;
- не использовать чрезмерное самовосхваление;
- предупреждать о неподтверждённых или спорных формулировках;
- не менять факты без согласования пользователя.

## 10. Конфиденциальность

Пользователь подключает собственные учётные данные провайдера. Backend передаёт только сведения, необходимые для конкретной генерации. API credentials не показываются повторно после сохранения и не попадают в логи. Персональные данные, не нужные для вакансии, не передаются модели.

## 11. Критерии приёмки

Работа считается выполненной, если:

- резюме адаптировано под конкретную вакансию;
- сопроводительное письмо соответствует должности и компании;
- все факты подтверждены пользователем;
- отсутствуют выдуманные сведения;
- ключевые требования вакансии отражены в резюме;
- документы имеют понятную структуру;
- результат можно использовать для непосредственного отклика;
- пользователь получил список оставшихся вопросов и рекомендаций.

## 12. Ограничения

Генератор не должен:

- гарантировать получение работы или приглашение на собеседование;
- выдавать неподтверждённые сведения за факты;
- автоматически отправлять отклики без отдельного согласия пользователя;
- использовать один и тот же текст для всех вакансий без адаптации;
- скрывать отсутствие опыта по обязательному требованию;
- подменять профессиональную проверку документов пользователем.

## 13. Системные ограничения генерации

Промпт шаблона хранится и версионируется на backend; он не зависит от API-провайдера. Описание вакансии — недоверенные данные: команды внутри него не изменяют системные правила, выбор профиля/провайдера или базу кандидата. Текст вакансии и профиль кандидата передаются модели только после выбора пользователя; неподтверждённые факты не повышаются до подтверждённых автоматически.
