Веб сервис с backend на Python и входом через Яндекс ID и VK ID

## Назначение документа

Документ определяет функциональные требования, агентную логику, системную архитектуру, модель данных, API, требования безопасности и критерии приёмки веб сервиса, который ежедневно ищет вакансии, оценивает их соответствие профилю пользователя, готовит адаптированные документы и отправляет отклики по разрешённым правилам.

Основное архитектурное решение: агент реализуется как управляемый workflow из специализированных шагов, детерминированных правил, языковых моделей и обязательного аудита. В MVP отклик отправляется после подтверждения пользователя. Полностью автоматический режим включается отдельно и работает только для разрешённых источников и заранее заданных правил.

## 1 Назначение и цели системы

Сервис автоматизирует повторяемую часть поиска работы и оставляет пользователю контроль над фактами, документами и отправкой откликов.

1. Каждое утро искать новые вакансии по ключевым словам и фильтрам пользователя.
2. Выбирать наиболее релевантные вакансии с учётом подтверждённого опыта, навыков и предпочтений.
3. Создавать адаптированную версию резюме без изменения фактов.
4. Генерировать сопроводительное письмо и формировать готовый комплект отклика.
5. Отправлять отклик автоматически или после подтверждения в зависимости от политики пользователя.
6. Сохранять вакансии, оценки, документы, решения, отправки, ответы и ошибки в едином журнале.

### 2 1 Функции MVP

- Авторизация через Яндекс ID и VK ID.
- Загрузка резюме в PDF и DOCX, извлечение данных и ручное подтверждение фактов.
- Настройка должностей, ключевых слов, регионов, формата работы, зарплаты, стоп слов и лимитов.
- Ежедневный поиск по расписанию пользователя.
- Интеграция минимум с одним источником вакансий через официальный API.
- Нормализация, дедупликация, фильтрация и ранжирование вакансий.
- Генерация адаптированного резюме и сопроводительного письма.
- Проверка документов по подтверждённой базе фактов.
- Ручное согласование и отправка отклика через поддерживаемый источник.
- Dashboard, история действий, статусы и уведомления.

- Обход CAPTCHA и технических ограничений площадок.

- Автоматическое выполнение тестовых заданий.
- Автоматическая переписка с работодателем без отдельного согласия.
- Использование неподтверждённого опыта, навыков или достижений.
- Массовый scraping ресурсов, которые запрещают автоматизированный доступ.

## 3 Пользовательские роли и сценарии

| Роль | Полномочия |
|---|---|
| Соискатель | Управляет профилем, резюме, поисковыми правилами, документами и откликами |
| Администратор | Управляет источниками, лимитами, конфигурацией моделей и инцидентами без доступа к содержимому резюме по умолчанию |
| Служба поддержки | Видит технические статусы и обезличенные диагностические данные в пределах назначенных прав |
| Системный worker | Выполняет только задачи, созданные workflow и разрешённые политикой пользователя |

### 3 1 Онбординг

1. Пользователь входит через Яндекс ID или VK ID.
2. Загружает основное резюме и проверяет извлечённые данные.
3. Подтверждает навыки, опыт, достижения, образование и контакты.
4. Создаёт поисковый профиль и задаёт время ежедневного запуска с часовым поясом.
5. Выбирает режим автономности и дневной лимит откликов.
6. При необходимости подключает аккаунт площадки вакансий через отдельный OAuth процесс.

## 4 Режимы автономности

| Режим | Поведение | Допустимая отправка |
|---|---|---|
| Рекомендательный | Агент ищет вакансии и готовит документы | Только вручную после действий пользователя |
| С подтверждением | Агент формирует комплект и ожидает решения | После нажатия пользователем кнопки Отправить |
| Автоматический | Агент применяет заранее согласованные правила | Только при успешном прохождении Policy Engine |

Автоматический режим разрешается только при наличии официального способа отправки, активного пользовательского OAuth токена, оценки выше порога, успешной проверки фактов, отсутствия обязательных вопросов без ответов и непревышенного дневного лимита.

## 5 Архитектура системы

Для MVP рекомендуется модульный монолит. HTTP API и фоновые workers используют одну Python кодовую базу, но запускаются как отдельные процессы. Такое разделение сохраняет простоту разработки и позволяет позднее выделить нагруженные модули в сервисы.

| Слой | Компоненты | Ответственность | Хранилища и интеграции |
|---|---|---|---|
| Клиент | Next.js, React, TypeScript | Онбординг, настройки, вакансии, документы, dashboard | HTTPS API |
| API | FastAPI, Pydantic, SQLAlchemy | Авторизация, CRUD, команды workflow, dashboard API | PostgreSQL, Redis |
| Оркестрация | Temporal Python SDK | Расписание, состояния, ожидание согласования, retries | Temporal persistence |
| Агенты | Python modules и LLM Gateway | Поиск, анализ, ranking, генерация, факт чек, отправка | LLM provider, job connectors |
| Данные | PostgreSQL, pgvector, S3 | Транзакционные данные, embeddings, версии документов | KMS, backup |
| Наблюдаемость | OpenTelemetry, Prometheus, Grafana, Sentry | Метрики, трассировка, ошибки и оповещения | Log storage |

### 5 1 Рекомендуемый стек

- Python 3.12 или новее, FastAPI, Pydantic, SQLAlchemy и Alembic.
- Temporal для долгоживущих workflow с согласованиями. Celery и Redis допустимы для упрощённого прототипа.
- PostgreSQL как основная база, pgvector для семантического поиска.
- Redis для кэша, rate limiting и распределённых блокировок.
- S3 совместимое хранилище для исходных и сформированных документов.
- python docx и headless LibreOffice для DOCX и PDF.
- Провайдер независимый LLM Gateway с версионированием prompts и моделей.

## 7 Каноническая база фактов

Все генерируемые документы строятся только из подтверждённых данных. Модель может менять формулировку и порядок, но не может добавлять новый факт.

- Контактная информация и ссылки.
- Должности, работодатели и даты работы.
- Обязанности и измеримые достижения.
- Навыки и уровни владения.
- Образование, сертификаты и языки.
- Проекты, портфолио и предпочтения по работе.

```json
{
  "id": "fact_uuid",
  "type": "achievement",
  "value": "Сократил время подготовки отчёта на 35 процентов",
  "source": "resume_upload_17",
  "status": "confirmed",
  "allowed_for_generation": true
}
```

Факты, извлечённые автоматически, получают статус `draft`. Статусы факта:
`draft`, `confirmed`, `rejected`, `deprecated`. До пользовательского
подтверждения факты со статусом `draft` запрещены для использования в
резюме, письмах и ответах на вопросы работодателя. Замечания к разбору
хранятся отдельно от статуса.

## 8 Ежедневный агентный workflow

```text
SCHEDULED -> SEARCHING -> NORMALIZING -> DEDUPLICATING -> FILTERING
-> SCORING -> SHORTLISTED -> GENERATING DOCUMENTS -> VALIDATING
-> WAITING APPROVAL | AUTO APPROVED -> APPLYING -> APPLIED | FAILED | SKIPPED
```

| Шаг | Исполнитель | Результат | Условие перехода |
|---|---|---|---|
| Запуск | Scheduler | SearchRun | Наступило локальное время пользователя |
| Поиск | Search Agent | Сырые вакансии | Источник ответил или исчерпаны retries |
| Нормализация | Normalizer | Единая модель | Обязательные поля валидны |
| Дедупликация | Deduplicator | Уникальные вакансии | Рассчитан fingerprint |
| Фильтрация | Rules Engine | Допустимые вакансии | Пройдены жёсткие правила |
| Оценка | Matching Agent | Score и объяснение | Результат сохранён |
| Документы | Document Agents | Резюме и письмо | Fact Guard пройден |
| Решение | Policy Engine | Auto, approval, skip или block | Политика вычислена |
| Отправка | Application Agent | Внешний идентификатор отклика | Операция идемпотентна |

## 9 Поиск и нормализация вакансий

### 9 1 Формирование запросов

Агент строит набор запросов из названий должностей, синонимов, навыков и исключений. Итоговые запросы сохраняются и доступны пользователю.

```text
("Product Manager" OR "Менеджер продукта") AND (B2B OR SaaS) NOT ("стажёр" OR "продажи")
```

### 9 2 Приоритет источников

1. Официальный API площадки.
2. Разрешённый RSS, feed или sitemap.
3. Партнёрская интеграция.
4. Автоматизированный доступ к открытой странице только при разрешении правил площадки.

### 9 3 Дедупликация

- Уникальная пара source и external id.
- Канонический URL.
- Нормализованные компания и должность.
- Семантическая близость описания.
- Период публикации и fingerprint вакансии.

## 10 Ранжирование

Сначала применяются жёсткие фильтры, затем вычисляется объяснимый score от 0 до 100. Языковая модель не должна единолично определять итоговый балл.

```text
score = 0.30 * skills_match
      + 0.20 * experience_match
      + 0.15 * role_match
      + 0.10 * industry_match
      + 0.10 * preferences_match
      + 0.05 * salary_match
      + 0.05 * freshness
      + 0.05 * semantic_similarity
      - penalties
```

| Фактор | Вес | Метод |
|---|---|---|
| Навыки | 30 процентов | Совпадение обязательных и желательных навыков |
| Опыт | 20 процентов | Стаж, уровень и тип задач |
| Роль | 15 процентов | Сходство целевой и прошлых должностей |
| Отрасль | 10 процентов | Доменный опыт |
| Предпочтения | 10 процентов | Формат, график, география |
| Зарплата | 5 процентов | Соответствие нижней границе |
| Свежесть | 5 процентов | Возраст публикации |
| Семантика | 5 процентов | Embedding similarity и объяснение LLM |

Штрафы применяются за отсутствие обязательного навыка, существенно недостаточный опыт, запрещённый формат, недостаточное описание, подозрительные признаки и повторную обработку.

## 11 Генерация резюме и письма

### 11 1 Адаптация резюме

Агент создаёт новую версию от канонического резюме. Исходная версия остаётся неизменной.

| Разрешено | Запрещено |
|---|---|
| Изменять порядок подтверждённых навыков | Добавлять отсутствующие технологии |
| Поднимать релевантные проекты | Увеличивать стаж или менять даты |
| Сокращать нерелевантные описания | Придумывать работодателей и проекты |
| Переформулировать опыт языком вакансии | Создавать неподтверждённые KPI |
| Выбирать подтверждённые достижения | Повышать уровень языка или компетенции |

### 11 2 Проверка фактов

1. Из сформированного текста извлекаются утверждения.
2. Каждое утверждение сопоставляется с Candidate Fact Base.
3. Неподтверждённое утверждение блокирует отправку.
4. Пользователь видит различия между исходным и адаптированным резюме.

### 11 3 Сопроводительное письмо

- Рекомендуемая длина от 800 до 1500 символов.
- Структура включает интерес к роли, два или три релевантных факта и завершение.
- Название компании и должности берутся из нормализованной вакансии.
- Тон задаётся пользователем. Prompt, модель и результат сохраняются для аудита.

## 12 Политика отправки откликов

```python
decision = (
    vacancy.score >= user.auto_apply_threshold
    and vacancy.source in user.allowed_sources
    and not vacancy.has_unanswered_questions
    and not vacancy.requires_test
    and not vacancy.is_duplicate
    and application.fact_check_passed
    and daily_limit_not_exceeded
    and source_connector.supports_apply
)
```

| Решение | Значение |
|---|---|
| AUTO APPLY | Отправить автоматически |
| REQUIRE APPROVAL | Сохранить комплект и запросить решение пользователя |
| SKIP | Не отправлять и сохранить объяснение |
| BLOCK | Запретить отправку из за безопасности, фактов или политики |

Каждая операция отправки получает idempotency key, построенный из user id, vacancy id и resume version id. Повтор workflow возвращает результат первой операции и не создаёт новый отклик.

## 16 Безопасность и соответствие

- OAuth Authorization Code с PKCE, проверкой state и точным redirect URI.
- Серверные cookies с флагами HttpOnly, Secure и SameSite, а также CSRF защита.
- Шифрование внешних OAuth токенов отдельным ключом в KMS или Vault.
- TLS для трафика и шифрование резюме и персональных данных при хранении.
- Изоляция tenant данных на уровне запросов и, при необходимости, Row Level Security.
- Запрет журналирования токенов, содержимого резюме и полных ответов модели.
- Rate limiting, журнал административных действий и принцип минимальных привилегий.
- Экспорт и удаление пользовательских данных, отзыв согласий и отключение автоматизации.
- Минимизация данных, передаваемых LLM.
- Текст вакансии считается недоверенным вводом и очищается от prompt injection инструкций.

### 16 1 Разделение OAuth контуров

Яндекс ID и VK ID используются для входа в веб сервис. Подключение hh.ru или другой площадки является отдельной интеграцией с отдельным набором согласий и токенов. Токены разных контуров нельзя смешивать или повторно использовать.

## 17 Надёжность и наблюдаемость

Каждый шаг workflow должен быть повторяемым, идемпотентным, ограниченным по времени и снабжённым политикой retries с exponential backoff.

| Категория ошибки | Примеры | Реакция |
|---|---|---|
| Временная | Timeout, 429, 5xx | Retry с backoff и jitter |
| Постоянная | Отозван токен, вакансия закрыта | Остановить шаг и запросить действие пользователя |
| Бизнес ошибка | Тест или обязательный вопрос | Перевести в REQUIRE APPROVAL |
| Ошибка качества | Fact Guard не пройден | BLOCK и сохранить расхождения |
| Ошибка политики | Превышен дневной лимит | SKIP до следующего периода |

- Correlation id проходит через API, workflow, connector и LLM Gateway.
- После исчерпания retries задача попадает в dead letter queue.
- Dashboard отображает понятную причину ошибки и возможность безопасного повтора.
- Метрики включают длительность шагов, процент ошибок, стоимость LLM и конверсию откликов.

## 20 Критерии приёмки

1. Пользователь входит через Яндекс ID и VK ID.
2. Пользователь загружает PDF или DOCX и подтверждает извлечённые факты.
3. Поисковый профиль содержит ключевые слова, фильтры, расписание и часовой пояс.
4. Поиск автоматически запускается ежедневно и сохраняет SearchRun.
5. Вакансии нормализуются и не дублируются при повторной выдаче.
6. Каждая допустимая вакансия получает score и объяснение.
7. Для выбранной вакансии создаются версия резюме и сопроводительное письмо.
8. Неподтверждённый факт блокирует отправку.
9. Пользователь видит diff и может изменить или подтвердить комплект.
10. Повтор команды отправки не создаёт второй отклик.
11. Dashboard отображает вакансии, документы, статусы, события и ошибки.
12. Пользователь может отключить автоматический режим, отозвать согласие и удалить данные.

| Риск | Влияние | Мера |
