## Как читать источники совместно

SPEC-001 задаёт сценарий работы через CV Maker. SPEC-002 описывает более
широкий сервис. SPEC-003 детализирует фактическую базу опыта. Они не объявлены
заменами друг друга. Для затронутых расхождений сначала используй реестр
вопросов; не выбирай приоритет документа по названию или дате файла.

Все исходные разделы и примеры сохранены. Добавлены только служебные
реквизиты и ссылки. В SPEC-002 прежняя версия 1.0 в таблице обозначает
версию исходного содержания; версия 1.1 в реквизитах — оформление после
миграции. Исходная формулировка статуса внутри ТЗ не является доказательством
утверждения заказчиком.

## Форматы и служебные файлы

- Все действующие документы редактируются только в Markdown.
- [Старая Word-копия](archive/architecture-spec-job-search-ai-agent-v1.0.docx)
  сохранена без изменения как архив. Её основной текст и таблицы сверены
  с исходным Markdown; самостоятельных требований не обнаружено.
- Производные DOCX/PDF при необходимости создаются в `docs/exports/`.
  Их нельзя использовать вместо источника. Старую выгрузку не перезаписывай.
- [Генератор Word](../scripts/build_architecture_tz.py) читает SPEC-002.
  Это скрипт, а не дополнительный источник требований.
- [Проверка документации](../scripts/check_docs.py) проверяет реквизиты,
  регистрацию, локальные ссылки, UTF-8/LF и размещение документов.
  Она не проверяет продуктовые решения или фактическую работу приложения.

## Проверка перед завершением

Из корня проекта: `python scripts/check_docs.py`.
Если Python не в PATH, укажи абсолютный путь к доступному интерпретатору.
Для нового документа сначала используй шаблон, затем внеси его в реестр.
Внешние ссылки проверяются при использовании API; локальная проверка
не обращается в сеть и не подтверждает актуальность внешних интеграций.
