# ADR-001 — Единое хранение документации

## Контекст и основание

Пользователь поручил оформить AGENTS.md и собрать документы и ТЗ в одном
месте и виде по правилам текущего чата. До изменения три Markdown-источника
находились в корне и docs, рядом существовала Word-копия архитектуры.

## Варианты

- Оставить смешанные форматы: сохраняет прежние пути, но создаёт неоднозначность.
- Склеить всё в одно ТЗ: облегчает поиск файла, но скрывает различия области
  применения и требует неразрешённых продуктовых решений.
- Единая папка Markdown с реестром: сохраняет источники и делает связи явными.

## Решение

Рабочие документы находятся в `docs/` и имеют единые реквизиты и формат.
Корневой `AGENTS.md` задаёт поведение агента; `README.md` направляет в реестр.
Исходные требования сохранены, различия зарегистрированы отдельно.
Word-копия, совпадающая по содержанию, хранится только в архиве.
Экспортный скрипт размещён в `scripts/` и пишет в `docs/exports/`.

## Последствия и проверка

Пути изменились — их соответствия приведены в [архиве](../archive/README.md).
Новое расположение проверяется `scripts/check_docs.py`. Сохранность исходных
Markdown проверена сравнением содержания без добавленных реквизитов и
навигационной заметки; бинарная Word-копия сохраняет исходный SHA-256.
Продуктовые расхождения требуют отдельных решений; это ADR их не разрешает.
